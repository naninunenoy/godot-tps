# ADR-0003: コマンドはプレイヤー・システムの意図で定義する

- Status: Accepted
- Date: 2026-05-12

## Context

コマンドの粒度・命名をどう決めるかが曖昧だった。
例として「ゲーム終了ダイアログを開くコマンド」が候補に上がったが、
これは UI の実装詳細であり、コマンドに含めるべきか議論した。

## Decision

- コマンドは「プレイヤーまたはシステムの意図」で定義し、UI の実装詳細を含めない
- ダイアログの表示はコマンドハンドラの副作用であり、コマンドではない
- コマンドの対象階層は System / Scene / Object の 3 レベル
- **実行可能なコマンドは現在のシーンが管理する**（`IScene.AvailableCommands`）
- `IGameApi` がその一覧を外部に公開し、MCP からも問い合わせ可能にする

## Consequences

- コマンド名が UI に依存しないため、UI 変更の影響を受けない
- 現在のシーンが実行可能なコマンドを返すことで、不正なコマンドの送信をシーン側で制御できる
- 「タイトル画面では StartGame と Quit しか実行できない」といったテストが xUnit で書ける
