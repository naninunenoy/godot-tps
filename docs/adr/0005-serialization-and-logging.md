# ADR-0005: 用途別にシリアライズ形式とログ管理方式を定める

- Status: Accepted
- Date: 2026-05-12

## Context

ゲーム状態・ログの出力先が複数あり（テスト・MCP・LLM エージェント・デバッグファイル）、
それぞれで最適なフォーマットが異なる。
また、ログを文字列のまま扱うとテストが脆弱になる（メッセージ変更で壊れる）。

## Decision

**シリアライズ形式**

| 用途 | 形式 | 理由 |
|---|---|---|
| xUnit テスト（インプロセス） | オブジェクトそのまま | 直列化不要 |
| MCP → LLM エージェント | ToonEncoder（TOON 形式） | トークンコスト削減 |
| プロセス間ログ転送 | MessagePack | サイズ・速度効率 |
| デバッグ確認・ファイル保存 | JSONL | 人間が読める、`jq` で絞れる |

**ログ管理**

- ログは文字列でなく**構造化ログストア**（型付きイベントレコード）で管理する
- イベント種別は定数で管理し、文字列リテラルを直接テストコードに書かない
- `Microsoft.Extensions.Logging` のカスタム `ILoggerProvider` として実装し、既存の `_logger.LogDebug(...)` と統合する
- テストでは「コマンド送信後に期待するログイベントが記録されているか」をアサートする
- エラーレベル以上のログが出ていないことをすべてのテストで共通アサートとする

## Consequences

- ログイベントが型付きになるため、メッセージ文言の変更でテストが壊れない
- MCP から LLM にゲーム状態を返す際のトークンコストを抑えられる
- ログの監視・エラー検出をテストフレームワーク内で完結させられる
