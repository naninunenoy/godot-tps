# ADR-0007: Raycast の役割を「HUD フィードバック」と「ヒット判定」に分離する

- Status: Accepted
- Date: 2026-05-22

## Context

TPS の射撃では「照準が敵に当たっているか」を画面にフィードバックする機能と、「弾が実際にヒットしたか」を判定する機能が必要になる。
これらを単一の Raycast で兼ねる案（弾を生成せず即座にヒット判定する Hitscan 方式）と、役割を分離する案を検討した。

## Decision

Raycast を目的別に2本に分ける。

| Raycast | 実行者 | タイミング | 目的 |
|---|---|---|---|
| ADS フィードバック用 | `Player` Node | 毎フレーム（`_Process`） | 照準先に `Target` があるか判定し、`AimUpdatedCommand` を発行して HUD の照準色を変える |
| ヒット判定用 | `Bullet` Node | 毎フィジクスフレーム（`_PhysicsProcess`） | 前フレームから今フレームの移動区間を Raycast し、`Target` に当たったら `TargetHitCommand` を発行して `QueueFree()` |

弾は物理的に飛翔する実体として存在し、Hitscan（即時判定）は採用しない。

## 理由

- **フィードバックの目的が異なる**：ADS フィードバックは「今の照準で発射すれば当たるか」を示す予測であり、実際の弾道とは別物として扱う
- **弾の飛翔を視覚・音響演出に使いたい**：弾が飛ぶ様子をアニメーションやエフェクトで表現するために実体が必要
- **精度変化への拡張性**：将来 ADS 時の精度向上・移動中のブレなどを実装するとき、弾道が独立していると変更が局所化できる

## Consequences

- 毎フレーム ADS Raycast が走るためコストが発生するが、結果が変わらない場合（`isOnTarget` が前フレームと同じ）は `AimUpdatedCommand` を発行しないガードを入れて軽減している
- `Bullet` が `PhysicsRayQueryParameters3D` を毎フィジクスフレーム生成するため、弾数が多い場合は GC 負荷に注意が必要
- 「照準は当たっているが弾が外れる」状況が理論上発生しうる（弾の移動中に Target が移動した場合など）。現状 Target は静止するため問題ないが、動的 Target を追加する際は認識が必要
